Tests erkunden

Bestehende Qualitätssicherung

Tests im Projekt finden

Aufgabe

Suchen Sie im Projekt nach vorhandenen Tests:

  • Schauen Sie in den _*.yml-Dateien unter models/ nach data_tests
  • Prüfen Sie den Ordner tests/ auf eigenständige Test-SQL-Dateien
dbt test

Führen Sie die Tests aus und beobachten Sie die Ausgabe.

Testarten in dbt

Generic Tests (YAML)

In _*.yml-Dateien definiert. Eingebaute Tests:

  • unique
  • not_null
  • accepted_values
  • relationships

Singular Tests (SQL)

Eigene SQL-Dateien in tests/. Jede Query, die Zeilen zurückgibt, gilt als fehlgeschlagen.


-- tests/mein_test.sql
SELECT *
FROM {{ ref('...') }}
WHERE ???

Modell & Tests

Neues Modell absichern

Neues Modell erstellen

Aufgabe

Erstellen Sie ein neues Modell models/00_example/uebung4_{kuerzel}.sql, das Bestellpositionen mit Produktinformationen verbindet – ähnlich wie in Übung 03, aber mit zusätzlichen Spalten.


-- models/00_example/uebung4_{kuerzel}.sql
SELECT
    ???
FROM {{ ref('???') }} AS ???
JOIN {{ ref('???') }} AS ???
  ON ???
Tipp: Relevante Seed-Tabellen: webshop_position, webshop_produkt, webshop_bestellung. Welche Spalten eignen sich für Tests?

Tests in YAML definieren

Ergänzen Sie die YAML-Datei um Tests für Ihr Modell:


version: 2

models:
  - name: uebung4_{kuerzel}
    description: "???"
    columns:
      - name: ???
        data_tests:
          - not_null
      - name: ???
        data_tests:
          - ???
Tipp: Überlegen Sie, welche Spalten not_null sein sollten und ob es Spalten gibt, bei denen unique oder accepted_values sinnvoll wäre.

Tests ausführen


dbt run -s uebung4_{kuerzel}
dbt test -s uebung4_{kuerzel}

Aufgabe

Passen Sie Ihr Modell und die Tests an, bis alle Tests grün sind. Machen Sie einen Screenshot der erfolgreichen Test-Ausgabe.

Macros

Wiederverwendbare SQL-Logik

Vorhandene Macros analysieren

Aufgabe

Öffnen Sie den Ordner macros/ und schauen Sie sich die Dateien an:

  • Was machen die Macros hub.sql und sat.sql?
  • Wie werden sie in den Modellen unter models/03_il_rdv/ aufgerufen?
  • Welche Parameter werden übergeben?
Tipp: Macros nutzen Jinja-Syntax ({% macro ... %}) und generieren dynamisch SQL-Code. Vergleichen Sie ein Macro mit dem generierten SQL in target/compiled/.

Eigenes Macro schreiben

Aufgabe

Erstellen Sie ein einfaches Macro in macros/, das eine häufig benötigte SQL-Logik kapselt.


-- macros/uebung4_{kuerzel}.sql
{% macro ???(???) %}
    SELECT
        ???
    FROM {{ ref(???) }}
    WHERE ???
{% endmacro %}
Ideen: Ein Macro, das nur Zeilen ab einem bestimmten Datum filtert, oder eines, das eine Standard-Aggregation (COUNT, SUM) auf eine beliebige Tabelle anwendet.

Macro verwenden

Aufgabe

Rufen Sie Ihr Macro in einem neuen oder bestehenden Modell auf und prüfen Sie das Ergebnis:


-- models/00_example/uebung4_{kuerzel}_macro.sql
{{ ???('???') }}
				

dbt run -s uebung4_{kuerzel}_macro
