Vorbereitung

Git Branch & venv

Neuen Git Branch anlegen

Erstellen Sie einen eigenen Branch für diese Übung:


git checkout -b uebung03

Tipp: In VS Code können Sie Branches auch über die Status Bar (unten links) wechseln.

Virtuelle Umgebung aktivieren

🪟 Windows

.\.venv\Scripts\Activate.ps1

🍎 macOS / Linux

source .venv/bin/activate

cd willibald_dwh
dbt build

Hinweis: Stellen Sie sicher, dass dbt build fehlerfrei durchläuft, bevor Sie fortfahren.

Projekt erkunden

Verzeichnisstruktur & Databricks

dbt-Projektstruktur

Machen Sie sich mit der Verzeichnisstruktur unter willibald_dwh/ vertraut:

  • models/ – SQL-Modelle (Views/Tables)
  • macros/ – Wiederverwendbare SQL-Logik
  • seeds/ – CSV-Eingabedaten
  • snapshots/ – Historisierung
  • tests/ – Fachliche Tests
  • dbt_project.yml – Projektconfig
  • profiles.yml – Datenbankverbindung
  • packages.yml – Abhängigkeiten

Generiert: target/, logs/, dbt_packages/ – nicht manuell bearbeiten.

Databricks prüfen

Öffnen Sie den Databricks Workspace und navigieren Sie zu:

Catalog → hive_metastore → bis242_XX

Aufgabe

Finden Sie die durch dbt build erstellten Tabellen und Views. Schauen Sie sich die Daten in einigen Tabellen an – was fällt Ihnen auf?

Bestehende Modelle verstehen

Aufgabe

Öffnen Sie einzelne .sql-Dateien unter models/. Versuchen Sie zu verstehen, wie die Modelle aufgebaut sind:

  • Was macht {{ ref('...') }}?
  • Was steht in den _*.yml-Dateien?
  • Wie hängen seeds/, PSA-Views und RDV-Modelle zusammen?

Eigenes Modell

SQL-View erstellen

Aufgabenstellung

Aufgabe

Erstellen Sie ein neues dbt-Modell, das Bestellpositionen mit Produktinformationen zusammenführt.

  • Datei: models/00_example/uebung3_{kuerzel}.sql
  • Nutzen Sie {{ ref('...') }} statt direkter Tabellennamen
  • Mindestens ein JOIN zwischen zwei Quelltabellen
Tipp: Schauen Sie sich die Tabellen webshop_bestellung, webshop_position und webshop_produkt in den Seeds an.

Hilfestellung: SQL-Grundgerüst


-- models/00_example/uebung3_{kuerzel}.sql
SELECT
    ???
FROM {{ ref('???') }} AS ???
JOIN {{ ref('???') }} AS ???
  ON ???

Hinweis: Überlegen Sie, welche Spalten Sie aus den Seed-Tabellen webshop_position und webshop_produkt auswählen wollen und über welche Spalte der JOIN erfolgt.

Modell bauen & prüfen

  1. Modell bauen: dbt run -s uebung3_{kuerzel}
  2. In Databricks prüfen: Wurde der View erstellt?
  3. Stimmen die Daten? Führen Sie eine SELECT-Abfrage auf den View aus.

Dokumentation

YAML-Schema

Modell in YAML dokumentieren

Aufgabe

Erstellen Sie eine YAML-Datei models/00_example/_example__models.yml und dokumentieren Sie Ihr Modell:


version: 2

models:
  - name: uebung3_{kuerzel}
    description: "???"
    columns:
      - name: ???
        description: "???"
Tipp: Eine gute Dokumentation hilft anderen Teammitgliedern zu verstehen, was Ihr Modell macht und welche Spalten es enthält.
