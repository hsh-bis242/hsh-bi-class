Aufgabenstellung - ELT Entwicklung

Implementieren Sie das von Ihnen modellierte Sternschema in dbt.

  • Legen Sie Ihr Datenmodell im Schema "ol_dm" an.
  • Erstellen Sie dbt-Modelle (.sql files) um Ihr Sternschema auf dem Datenbankserver zu erzeugen und zu beladen.
  • Pushen Sie Ihr dbt-Projekt per git ins Github-Repository.

Hinweise zur technischen Modellierung

  • Zu jedem Ladezeitpunkt (loadingid) werden die Produktkategoriedaten stark verändert. Alle Daten im Fakt sollen deshalb auf einen Ladezeitpunkt gefiltert werden können.
  • Beachten Sie, dass die Zuordnung des Wohnorts zum Kunden multiaktiv ist. Hier sollte auf ein fachlich relevantes Datum eingeschränkt werden.

							models/05_dm_ol/dim_product.sql
							
								WITH cte_product AS (
									SELECT      brdg.sys_loadingid,
															hub_product.product_id,
															sat_product.description,
															sat_product.circumference,
															pt.description AS producttype,
															sat_product.price,
															sat_product.plantinglocation,
															sat_product.plantingdistance,
															hub_productcategory.productcategory_id,
															sat_productcategory.name AS productcategory_name,
															hub_supercategory.productcategory_id AS supercategory_id,
															sat_supercategory.name AS supercategory_name
										FROM      {{ ref("brdg_orderitem_all") }} brdg
										JOIN      {{ ref("hub_product") }} hub_product
										ON      	brdg.hkey_hub_product = hub_product.hkey_hub_product
										JOIN      {{ effective_sat("sat_product_context", "sat_product", "hkey_hub_product", "brdg") }}
										LEFT JOIN {{ ref("ref_producttype") }} pt
										ON      	pt.producttype = sat_product.producttype
										JOIN      {{ ref("hub_productcategory") }} hub_productcategory
										ON      	hub_productcategory.hkey_hub_productcategory = brdg.hkey_hub_productcategory
										LEFT JOIN {{ effective_sat("sat_productcategory_context", "sat_productcategory", "hkey_hub_productcategory", "brdg") }}
										LEFT JOIN {{ ref("hub_productcategory") }} hub_supercategory
										ON      	hub_supercategory.hkey_hub_productcategory = brdg.hkey_hub_supercategory
										LEFT JOIN {{ effective_sat("sat_productcategory_context", "sat_supercategory", "hkey_hub_productcategory", "brdg", "hkey_hub_supercategory") }}
									)
									SELECT DISTINCT {{ hashcolumn(source_model_name = "cte", list_columns = ["product_id", "sys_loadingid"], hashcolumn_name = "hkey_dim_product") }},
																cte.product_id,
																cte.description,
																cte.circumference,
																cte.producttype,
																cte.price,
																cte.plantinglocation,
																cte.plantingdistance,
																IFNULL(cte.productcategory_name, 'No category') AS productcategory_name,
																IFNULL(cte.supercategory_name, 'No super category') AS supercategory_name
									FROM          cte_product cte

									  LEFT JOIN {{ ref("lnk_webshoporderitem_delivery") }} lnk_delivery

										ON      	hub_dlvryaddrss.hkey_hub_deliveryaddress = brdg.hkey_hub_deliveryaddress
									  LEFT JOIN {{ effective_sat("sat_deliveryaddress_context", "sat_dlvryaddrss", "hkey_hub_deliveryaddress", "brdg") }}
									  LEFT JOIN {{ ref("ref_postalcode_federalstate") }} pc_fs
										ON      	pc_fs.postalcode = sat_dlvryaddrss.postalcode
									  LEFT JOIN {{ ref("federalstatecode") }} fs
										ON     	 	pc_fs.federal_state_key = fs.key
								)

								  FROM          (
																	SELECT	*
																	  FROM 	cte_delivery cte

																	SELECT	lh.loadingid AS sys_loadingid,
																					NULL AS deliverydate,
																					NULL AS deliveryservice_id,

							models/05_dm_ol/dim_customer.sql
							
								WITH cte_customer_residence AS (
									SELECT      lnk.hkey_hub_customer,
															sat.sys_loadingid,
															sat.sys_loadingid_validto, 
															lnk.validfrom,
															IFNULL(sat.validto, DATE '9999-12-31') AS validto,
															sat.street,
															sat.housenumber,
															sat.addresssupplement,
															sat.postalcode,
															sat.city,
															fs.federalstate_code,
															fs.federalstate_name,
															sat.country
									FROM      	{{ ref("lnk_customer_residence") }} lnk
									JOIN      	{{ ref("lsat_customer_residence_context") }} sat
										ON    	  sat.hkey_lnk_customer_residence = lnk.hkey_lnk_customer_residence
									LEFT JOIN 	{{ ref("ref_postalcode_federalstate") }} pc_fs
										ON    	  pc_fs.postalcode = sat.postalcode
									LEFT JOIN 	{{ ref("federalstatecode") }} fs
										ON    	  pc_fs.federal_state_key = fs.key
									WHERE     	sat.sys_cdc != 'D'
								),
								cte_customer AS (
									SELECT      brdg.sys_loadingid,
															hub_customer.customer_id,
															sat_customer.firstname,
															sat_customer.lastname,
															sat_customer.gender,
															sat_customer.birthdate,
															cte_residence.postalcode,
															cte_residence.city,
															cte_residence.federalstate_code,
															cte_residence.federalstate_name,
															CAST(cte_residence.country AS VARCHAR) AS country
									FROM      	{{ ref("brdg_orderitem_all") }} brdg
									JOIN      	{{ ref("hub_customer") }} hub_customer
										ON    	  hub_customer.hkey_hub_customer = brdg.hkey_hub_customer
									LEFT JOIN 	{{ effective_sat("sat_customer_context", "sat_customer", "hkey_hub_customer", "brdg") }}
									LEFT JOIN 	{{ ref("csat_webshoporderitem_kpi") }} sat_wsoi
										ON    	  sat_wsoi.hkey_hub_webshoporderitem = brdg.hkey_hub_webshoporderitem
									 AND      	sat_wsoi.sys_loadingid = brdg.sys_loadingid
									JOIN      	{{ ref("loading_history") }} lh
										ON      	lh.loadingid = brdg.sys_loadingid
									LEFT JOIN		cte_customer_residence cte_residence
										ON      	cte_residence.hkey_hub_customer = brdg.hkey_hub_customer
									 AND      	cte_residence.sys_loadingid >= brdg.sys_loadingid 
									 AND      	cte_residence.sys_loadingid_validto > brdg.sys_loadingid
									-- Evaluating the business validity using the date of the order would be a good idea,
									-- but we have to consider that there might be two orders with different orderdate in the same loading.
									-- that would lead to non unique hkey_dim_customer values.
									-- for future models we should consider to have the customer residence as an additional dimension.
									 AND 	 	  cte_residence.validfrom <= lh.loadingts
									 AND 	 	  cte_residence.validto >= lh.loadingts
									
								)
								SELECT DISTINCT	{{ hashcolumn(source_model_name = "cte", list_columns = ["customer_id", "sys_loadingid"], hashcolumn_name = "hkey_dim_customer") }},
																IFNULL(cte.customer_id, 0) AS customer_id,
																IFNULL(cte.firstname, 'No') AS firstname,
																IFNULL(cte.lastname, 'Customer') as lastname,
																cte.gender,
																cte.birthdate,
																cte.postalcode,
																cte.city,
																IFNULL(cte.federalstate_code, 'XX') AS federalstate_code,
																IFNULL(cte.federalstate_name, 'Unbekannt') AS federalstate_name,
																IFNULL(CAST(cte.country AS VARCHAR), 'Germany') AS country
								FROM          (
												SELECT      *
													FROM      cte_customer
												 UNION ALL
												SELECT      lh.loadingid AS sys_loadingid,
																		NULL AS customer_id,
																		NULL AS firstname,
																		NULL AS lastname,
																		NULL AS gender,
																		NULL AS birthdate,
																		NULL AS postalcode,
																		NULL AS city,
																		NULL AS federalstate_code,
																		NULL AS federalstate_name,
																		NULL AS country
													FROM      {{ ref("loading_history") }} lh
												) cte

Beispiellösung - Fakten und Dimensionen (6/6)

						models/05_dm_ol/dim_association.sql
						
							WITH cte_association AS (
								SELECT  brdg.sys_loadingid,
												hub_association.association_id,
												sat_association.discount1,
												sat_association.discount2,
												sat_association.discount3
								FROM  	{{ ref("brdg_orderitem_all") }} brdg
								JOIN  	{{ ref("hub_association") }} hub_association
									ON  	hub_association.hkey_hub_association = brdg.hkey_hub_association
								JOIN  	{{ effective_sat("sat_association_context", "sat_association", "hkey_hub_association", "brdg") }}
							)
							SELECT DISTINCT {{ hashcolumn(source_model_name = "cte", list_columns = ["association_id", "sys_loadingid"], hashcolumn_name = "hkey_dim_association") }},
															cte.association_id AS association_name,
															cte.discount1,
															cte.discount2,
															cte.discount3
							 FROM          	cte_association cte
							 UNION ALL
							SELECT          {{ hashcolumn(source_model_name = "t", list_columns = ["association_id", "sys_loadingid"], hashcolumn_name = "hkey_dim_association") }},
															t.* EXCLUDE (association_id, sys_loadingid)
							FROM          	(
											SELECT  NULL AS association_id,
															lh.loadingid AS sys_loadingid,
															'No association' AS association_name,
															NULL AS discount1,
															NULL AS discount2,
															NULL AS discount3
												FROM  {{ ref("loading_history") }} lh
											) t

Beispiellösung - Datumsdimensionen

Im Fakt sind drei Datümer angelegt: Bestell-/Kauf-, Wunsch-, und Lieferdatum. Gängige OLAP- und BI-Tools erwarten pro Datum eine Dimension. Aus der Datumsdimensions-Tabelle werden deshalb drei Views abgeleitet:

						models/05_dm_ol/dim_deliverydate.sql,

						models/05_dm_ol/dim_orderdate.sql,

						models/05_dm_ol/dim_requesteddate.sql
						
							{{ config(materialized="view") }}
							SELECT  hkey_dim_date AS {{ "hkey_" + this.name }},
											{{ dbt_utils.star(ref("dim_date"), except=["hkey_dim_date"], relation_alias="dt") }}
							  FROM	{{ ref("dim_date") }} dt

❗ Hier böte sich ein Makro an, da drei Mal der selbe Code verwendet wird ❗

Implementierung in dbt

In dbt müssen lediglich für jede Tabelle / View eine *.sql-Datei im Projektordner unter "models" angelegt werden.

Anschließend kann mit dbt run das Sternschema auf dem Server angelegt werden.

Ergebnis der Übung

  • Ihre Übungsdatenbank enthält Dimensionen- und Faktentabellen und diese enthalten Daten aus dem DWH.
  • Die Faktentabelle sollte auf Granularität der Bestellposition pro Ladezeitpunkt sein.
  • Im main-Branch Ihres Github-Repository ist das dbt-Modell entsprechend implementiert
