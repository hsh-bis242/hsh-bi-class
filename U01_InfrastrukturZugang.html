Beitritt zu einer Übungsgruppe

Bitte suchen Sie sich einen Übungspartner und treten mit ihm gemeinsam einer der leeren bereits in Moodle angelegten Gruppen (BI2300X) bei.

Zugang zu Microsoft Azure und BI-Server

Sobald Sie und ihre Übungspartner einer Übungsgruppe beigetreten sind, melden Sie sich bitte bei uns. Wir werden Ihnen dann ihre persönlichen Zugangsdaten zum Azure und BI-Server kommunizieren.

Bitte versuchen Sie sich mit den erhaltenen Benutzerdaten in Microsoft Azure einzuloggen. Beachten Sie auch die Hinweise auf der folgenden Folie.

Hinweise zum Microsoft Azure Account

Ändern Sie Ihr Passwort mit der ersten Anmeldung und teilen Sie das neue Passwort einem der Dozenten in einer Nachricht per Moodle mit.

Mit Ihrer Passwortänderung bestätigen Sie, dass Sie mit Ihrer (Team-)UID sorgsam umgehen werden und Probleme direkt an den Dozenten melden. Starten Sie nur die in den Übungen angegebenen Services in den angegebenen Konfigurationen. Löschen bzw. Pausieren Sie die Services wie angegeben. Im Zweifel löschen Sie Services und kontaktieren Sie Ihren Dozenten. Es gilt die Benutzungsordnung für die Informationsverarbeitungssysteme der Hochschule Hannover (IVS-BO) (siehe service.it.hs-hannover.de/media/documents/ivs-bo.pdf)

Eine Weitergabe der UID und des Passwortes an Dritte ist nicht zulässig!

Hochfahren einer SQL-Datenbank in Azure

Führen Sie bitte folgendes Statement in Azure Powershell aus: 

					# Set an admin login and password for your server
$groupName = "bi23020"
$password = "ChangeYourAdminPassword1OrStickWithm7eUAFZnD8aF"

# The SubscriptionId in which to create these objects
$SubscriptionId = '1f75bacb-8d7d-4e96-87cb-f7e4216886e5'
# Set server name - the logical server name has to be unique in the system
$serverName = $groupName + "-exercise-sql"
$resourceGroupName = "rgBI"
$location = "westeurope"
# The sample database name
$databaseName = $groupName + "-db"
# The ip address range that you want to allow to access your server
$startIp = "0.0.0.0"
$endIp = "255.255.255.255"

# Set subscription 
Set-AzContext -SubscriptionId $subscriptionId 

# Create a server with a system wide unique server name
$server = New-AzSqlServer -ResourceGroupName $resourceGroupName `
	-ServerName $serverName `
	-Location $location `
	-SqlAdministratorCredentials $(New-Object -TypeName System.Management.Automation.PSCredential -ArgumentList $groupName, $(ConvertTo-SecureString -String $password -AsPlainText -Force))

# Create a server firewall rule that allows access from everywhere
$serverFirewallRule = New-AzSqlServerFirewallRule -ResourceGroupName $resourceGroupName `
	-ServerName $serverName `
	-FirewallRuleName "AllAccess" -StartIpAddress $startIp -EndIpAddress $endIp

# Create a serverless database with AdventureWorks sample data
$database = New-AzSqlDatabase  -ResourceGroupName $resourceGroupName `
	-ServerName $serverName `
	-DatabaseName $databaseName `
	-Edition "GeneralPurpose" `
	-Vcore 2 `
	-ComputeGeneration "Gen5" `
	-ComputeModel Serverless `
	-SampleName "AdventureWorksLT"

Tragen Sie im Script oben bitte Ihren Gruppennamen und ein beliebiges Passwort ein.

Import des Übungsdatensatzes

Wenn Sie das Script auf der vorherigen Folie ausgeführt haben, wird automatisch der Übungsdatensatz AdventureWorksLT in die Datenbank geladen. Für Sie ist nichts weiter zu tun.

Bitte prüfen Sie den Zugriff auf Ihre Datenbankinstanz mit einem DBMS-Tool Ihrer Wahl. Wir empfehlen Microsoft SQL Server Management Studio 19.

Import weiterer Übungsdatensätze

Der Übungsdatensatz wird Ihnen in einem Azure-Speicherkonto zur Verfügung gestellt. Mit folgendem Befehl (bitte wieder in Azure Powershell ausführen) wird der Importvorgang gestartet:

						# Set an admin login and password for your server
$groupName = "bi23020"
$password = "ChangeYourAdminPassword1OrStickWithm7eUAFZnD8aF"

# The SubscriptionId in which to create these objects
$SubscriptionId = '1f75bacb-8d7d-4e96-87cb-f7e4216886e5'
# Set server name - the logical server name has to be unique in the system
$serverName = $groupName + "-exercise-sql"
$resourceGroupName = "rgBI"
# The sample database name
$databaseName = $groupName + "bikeshop-db"

# Import bacpac to database
$importRequest = New-AzSqlDatabaseImport -ResourceGroupName $resourceGroupName `
	-ServerName $serverName `
	-DatabaseName $databaseName `
	-DatabaseMaxSizeBytes 100GB `
	-StorageKeyType "StorageAccessKey" `
	-StorageKey $(Get-AzStorageAccountKey -ResourceGroupName $resourceGroupName -StorageAccountName $storageAccountName).Value[0] `
	-StorageUri "https://$storageaccountname.blob.core.windows.net/$storageContainerName/$bacpacFilename" `
	-Edition "Standard" `
	-ServiceObjectiveName "S0" `
	-AdministratorLogin "$adminSqlLogin" `
	-AdministratorLoginPassword $(ConvertTo-SecureString -String $password -AsPlainText -Force)

Es kann ein paar Minuten dauern, bis der oben genannte Befehl abgeschlossen ist.

Anlegen eines Git-Repositories in Azure Devops

Rufen Sie bitte dev.azure.com in einem Webbrowser auf und loggen Sie sich nach einem Klick auf "Start free" mit Ihren Benutzerdaten ein.

Sie werden nun aufgefordert eine neue Organisation anzulegen. Benennen Sie diese bitte nach dem Schema "hsh-bi230XX". Als Projektnamen tragen Sie bitte "Uebung-BI23" ein.

Berechtigen Sie uns auf Ihr Projekt (1/2)

Berechtigen Sie uns zum Zugriff auf Ihr Devops-Projekt. Klicken Sie im Einstiegsbildschirm Ihrer Organisation (dev.azure.com/hsh-bi230XX) auf "Organization Settings". Dann wählen Sie "Users" und klicken auf "Add Users".

Berechtigen Sie uns auf Ihr Projekt (2/2)

Nun fügen Sie den Benutzer bi23001@hshannoverde.onmicrosoft.com mit dem Access Level Basic Ihrer Organisation hinzu und ordnen ihm auch direkt Ihr Projekt Uebung-BI23 zu.
