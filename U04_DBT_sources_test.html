Anlegen von dbt source yml files

Jedes Objekt wird in der yml nach dem gleichen Muster angelegt

  • name: Der Objektname oder Spaltenname in der Datenbank
  • columns: mit "-" markierte Liste der Spalten die getestet werden sollen
  • tests: mit "-" markierte Liste der tests die auf der Spalte ausgeführt werden sollen
  • ACHTUNG bei yml files sind Einrückungen der Textblöcke relevant, hier als Tipp eine extension für yml files im visual studio code editor installieren

Anlegen von dbt source yml files

Es existieren 4 Standard tests in dbt

  • unique: Testet ob die Werte in einer Spalte eindeutig sind
  • not_null: Testet ob leere oder missing Werte in der Spalte vorhanden sind
  • relationships: Testet die Werte der Spalte gegegn die Werte einer anderen Spalte. Im Beispiel wird geprüft, ob alle Kunden-surrogate-Keys im hub_kunde auch im link lnk_bestellung_kunde enthalten sind
  • accepted_values: Testet ob Werte außerhalb einer fest definierten Werteliste in der Spalte auftreten

Anlegen von dbt source yml files

Tests ausführen

  • In Visual Studio Code könnt Ihr in der unteren Arbeitsfläche ein terminal Fenster öffnen
  • Um dbt Befehle ausführen zu können müsst Ihr euch im Userverzeichnis dev\bis242ws230x\willibald_dm\ befinden, ggf. müsst Ihr also noch cd .\willibald_dm\ ausführen weil Ihr ein Verzeichnis höher die terminal Session startet
  • Die tests könnt ihr ausführen mit dem Befehl dbt test --select source:* dieser Befehl testet alle source yml files
  • Alternativ könnt ihr auch spezifisch den internen Namen der yml files nutzen, der ganz oben im file definiert wurde dbt test --select source:willibald_dwh_sats
  • Oder auch spezifisch aus Gründen der Übersichtlichkeit ein Objekt testen dbt test --select source:willibald_dwh_sats.hub_kreditkarte

Tests ausführen

Wenn ein test failed heißt dies nicht das Ihr etwas falsch gemacht hat sondern eurer Test hat Probleme oder Fehler in den Daten gefunden, hier ein Beispiel. Die Zahl hinter dem FAIL zeigt die Anzahl der rows an die den test nicht bestanden haben

Tests ausführen

Wenn Ihr einen Fehler im Code habt zeigt euch dbt dies mit einem Error an, hier ein Beispiel, in diesem Fall habt Ihr ein Syntax Fehler in einer yml

Ergebnis der Übung

  • Alle Satelliten, Hubs, Links aus dem dwh_sl schema sind mit tests in den yml files angelegt
  • Die tests müssen ausführbar sein
  • Die Fragen in den vorgegeben yml-Files wurden beantworten
  • Die tests müssen nicht immer fachlich sinnvoll sein, dies könnt Ihr in der kurzen Übungs-Zeit nicht komplett bewerten
  • Für einen Notenverbesserung und erfolgreiche Absolvierung würden wir die Vollständigkeit der yml files prüfen und diese ausführen, wenn Ihr 3 von 5 Fragen zufriedenstellend beantworten konntet gilt dies als erfolgreich
  • Vergesst nicht die Änderungen in eurer git-repo zu pushen, hier könnt Ihr auch schon gerne branching ausprobieren, wenn Ihr möchtet
